# Chinese tone pair drill

Web app for drilling Chinese tone pairs (tone of the first character × tone of the second character). The user selects which of the 20 tone pairs to practice and how many questions to answer, listens to audio, guesses the pair, and reviews results and per-pair statistics.

## Running

Requires [bun](https://bun.sh).

```sh
bun install   # first time only
bun run dev   # open the printed http://localhost:5173
```

Other scripts:

- `bun run build` — type-check and build to `dist/` (includes a copy of the audio files)
- `bun run preview` — serve the built `dist/`
- `bun run lint` — run oxlint

## Data

- `data.json` — list of words with their tone pattern and audio filename (generated by `1-parse-cedict.py` + `2-build-json.py`)
- `audio/` — pronunciation mp3s (`cmn-*.mp3`), sourced from https://github.com/hugolpz/audio-cmn

Both live in the repo root; the app itself doesn't serve them, so you must make them available somewhere and point the app at them.

## Configuration

The paths to the data file and audio files are set with environment variables (see `.env.example`). Copy it to `.env.local` to set them without editing code. If a variable is unset the app falls back to `/data.json` and `/audio`, but nothing in the repo serves those paths — set both:

- `VITE_DATA_URL` — URL of the word data JSON
- `VITE_AUDIO_BASE_URL` — base URL of the pronunciation mp3s (no trailing slash)

Example serving the repo root from a local static server:

```sh
# terminal 1: serve data.json and audio/
bunx serve . -l 8000
# terminal 2: run the app
bun run dev
```

With `.env.local`:

```sh
VITE_DATA_URL=http://localhost:8000/data.json
VITE_AUDIO_BASE_URL=http://localhost:8000/audio
```

Absolute URLs work too, e.g. `VITE_AUDIO_BASE_URL=https://cdn.example.com/audio`. The variables only control what the app requests — the files themselves still need to be served from those locations.
