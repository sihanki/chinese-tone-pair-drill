# Chinese tone pair drill

Web app for drilling Chinese tone pairs (tone of the first character × tone of the second character). The user selects which of the 20 tone pairs to practice and how many questions to answer, listens to audio, guesses the pair, and reviews results and per-pair statistics.

## Running

Requires [bun](https://bun.sh).

```sh
bun install   # first time only
bun run dev   # open the printed http://localhost:5173
```

Other scripts:

- `bun run build` — type-check and build to `dist/` (includes a copy of the audio files)
- `bun run preview` — serve the built `dist/`
- `bun run lint` — run oxlint

## Data

- `data.json` — list of words with their tone pattern and audio filename (generated by `1-parse-cedict.py` + `2-build-json.py`)
- `audio/` — pronunciation mp3s (`cmn-*.mp3`), sourced from https://github.com/hugolpz/audio-cmn

`public/audio` and `public/data.json` are symlinks into the repo root so the app serves them as static assets.

## Configuration

The paths to the data file and audio files can be overridden with environment variables (see `.env.example`). Copy it to `.env.local` to adjust without editing code:

- `VITE_DATA_URL` — URL of the word data JSON. Default: `/data.json`
- `VITE_AUDIO_BASE_URL` — base URL of the pronunciation mp3s (no trailing slash). Default: `/audio`

```sh
VITE_DATA_URL=/data.json VITE_AUDIO_BASE_URL=/audio bun run dev
```

Absolute URLs work too, e.g. `VITE_AUDIO_BASE_URL=https://cdn.example.com/audio`. The paths only control what the app requests — the files themselves still need to be served from those locations.
